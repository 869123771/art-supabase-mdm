# 工作中心与标准作业

工作中心负责生产资源与规则配置；作业模板负责任务清单和评分；工艺路线负责产品、工序、工作中心及模板的关联。数据和查询统一通过 `@mdm/api` 导出。

- 模板任务作为一份原子文档保存，数据库验证任务内容并计算总分。复制剔除主键、租户及审计字段。
- 工作中心编号、名称按租户唯一。主工序位默认是自身，也可以引用一个未占用的其他工作中心；服务器拒绝循环关联和跨租户引用。
- 人员来自生产人员配置。临时调整使用左闭右开的时间区间，服务器拒绝重叠；`mdm_center_effective_personnel` 按指定时刻的安排，仅返回当前租户、当前启用的生产人员。停用会排除常驻和临时加入人员，重新启用后按原安排恢复；查询不修改配置。该函数不是历史考勤回放，未来 MES 报工应另存当时的人员身份快照。
- 工作中心设备引用设备主档，设备不能被重复占用，一个中心最多配置一台主设备。
- 基本资料可引用同租户启用的工序控制码；活动信息以独立子表维护活动名称、类型、维护规则、两位小数基数、时间单位、计划/汇报公式、倒冲和备注，保存工作中心时保持原子提交。
- 关联设备支持一次选择多台尚未占用的设备；批量关联时可将首台设为主设备，已有设备仍按单台调整主设备与投入/产出点。
- “更新产品工艺”把当前工作中心规则同步到已关联的工艺工序，并记录同步时间。
- 常用配置只作为后续新增工作中心的默认值。配置涵盖报工、投料、检验、人员、排程和自动化时间。
- 二维码保存独立且不可修改的 `qr_token`，导出的 Excel 嵌入二维码图片。设备采集端或三色灯应使用同一个 token 建立映射。

导入使用导出表头：工作中心、名称、所属产线编码、主工序位、人员安排、人员工号、人数、排序、备注及各项规则。多个人员工号或多选规则用分号分隔；主工序位必须是已存在的工作中心。未填写规则沿用租户常用配置；无效工号、字典值和时间会按行提示，整批保存保持原子性。每次最多导入 1000 行，普通导出最多 10000 行，二维码标签最多 500 个。

报工规则、自动开始及自定义报工时间是生产执行端的配置契约。当前 MES 模块尚无派工、机器采集和报工执行服务；这里不创建虚构生产任务或后台自动报工记录。执行服务接入后应读取工艺规则快照与有效人员函数。

权限按各页面下的按钮分配。生产参选 RPC 只暴露当前租户的产品/设备身份字段，不开放设备原值等完整台账资料。普通角色的真实数据库写入、绑定原子性和人员时间边界由 `supabase/tests/operation_template_work_center_test.sql` 在回滚事务中验证。

引用完整性：`mdm_work_center.person_ids` 和生产人员的 `permission_department_ids` 仍是唯一可写的业务值。数据库在同一事务内维护 `app_private.mdm_work_center_person_reference` 与 `app_private.mdm_person_department_reference` 两张内部引用索引，以租户复合外键阻止删除仍被引用的人员或部门；来源删除只级联清理索引，不删除目标档案或历史调整。索引没有独立业务生命周期，审计沿用来源记录；RLS 开启且客户端、服务角色均无直接访问权限，不应通过 API 维护或计入主数据目录。

同步触发器覆盖插入和所有更新，并按最终数组是否变化决定同步；不能限定为 `UPDATE OF person_ids`，因为切换人数模式时已有校验触发器会间接清空数组。数组去重仅用于内部索引，不修改原接口值；非法存量引用使迁移整体失败，不自动清洗业务记录。`supabase/tests/mdm_array_references_test.sql` 验证删除限制、权限不可见的来源、无效批量写入回滚、解除引用、模式切换、来源级联清理及内部权限。并发一致性依赖 PostgreSQL 原生外键，双连接竞争测试本次因 MCP 传输异常未完成，不将其计为已验证。
